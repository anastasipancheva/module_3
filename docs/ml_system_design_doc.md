## 1. Цели и бизнес-требования

### 1.1 Зачем идем в разработку продукта?

* **Контекст:** Mindly — приложение для саморазвития и велнеса. Ключевая проблема, которую сформулировал клиент: *«Пользователь открывает приложение на второй день, и агент спрашивает его имя заново»*. Это разрушает ощущение персонального коуча и является главной причиной оттока в первые 7 дней.
* **Unit-экономика:** В приложениях для саморазвития Day-7 Retention напрямую определяет LTV. По данным из отчётов Appsflyer, медианный Day-7 для wellness-приложений — 12%. Продукты с выраженной персонализацией (рекомендательные системы, адаптивные тренировки) показывают 18–22%.
* **Эффект от использования ML:** Если AI-коуч «помнит» пользователя, снижается когнитивная нагрузка (не надо повторять контекст каждый раз), формируется эмоциональная привязанность к продукту (*«он меня знает»*) и пользователь охотнее возвращается, чтобы отчитаться и получить фидбэк.
* **Успех итерации:** Создать MVP AI-коуча с долгосрочной памятью, готовый к демонстрации инвесторам 30 мая 2026. Демо должно показать: агент помнит факты из прошлой сессии без повторного ввода данных.

### 1.2 Бизнес-требования и ограничения

| № | Требование | Источник | Тип |
| --- | --- | --- | --- |
| 1 | Агент помнит пользователя между сессиями | Звонок с клиентом | Stated |
| 2 | Минимум две персоны: «Tough Love» и «Wellness Friend» | Звонок с клиентом | Stated |
| 3 | Изоляция данных: пользователь A не видит данные пользователя B | Звонок с клиентом | Stated |
| 4 | Пользователь может удалить свои данные (тему или всё) | Звонок с клиентом | Stated |
| 5 | Стриминг токенов — ответ появляется постепенно | Требование UX | Inferred |
| 6 | Готовность к инвестиционному демо 30 мая 2026 | Звонок с клиентом | Stated |
| 7 | Работа через API (не локальная модель) для упрощения деплоя | Практическое решение команды | Assumed |
| 8 | Соответствие GDPR: право на удаление данных | Правовой стандарт ЕС | Assumed |
| 9 | Стоимость демо не превышает $10 | Стартап-ограничения | Assumed |
| 10 | CLI или веб-UI (не мобильное приложение для MVP) | Минимальный скоуп | Assumed |

**Предположения, требующие валидации:**

* **A7:** Клиент согласен использовать OpenRouter (сторонний API), а не собственный инстанс модели.
* **A8:** GDPR не требует шифрования at-rest для MVP (только для production).
* **A10:** Инвестиционное демо проводится на ноутбуке, не на реальном пользовательском трафике.

**Описание бизнес-процесса пилота:** Инвестор выступает в роли пользователя. В рамках демо он проводит стартовую сессию с агентом, сообщает ключевые факты (цели, ограничения), закрывает приложение. При повторном открытии агент выстраивает приветствие и контекст на основе сохраненной информации.

### 1.3 Что входит в скоуп проекта/итерации, что не входит

* **Входит в MVP:**
* Веб-UI (Streamlit): вход по User ID, выбор персоны.
* Долгосрочная память через Mem0 + ChromaDB (persistent across restarts).
* Две персоны с разными системными промптами.
* Изоляция тенантов (user_id фильтр во всех операциях).
* Управляемое забывание: точечное и полное.
* Стриминг ответов.
* Базовый бенчмарк памяти (Mini LongMemEval).
* Docker-образ для воспроизводимого запуска.
* Логирование всего pipeline.


* **НЕ входит в MVP (Phase 2):**
* Мобильный клиент (React Native / Flutter).
* Интеграция с Google Calendar и Apple Health.
* Проактивные push-уведомления.
* A/B тестирование персон.
* Production инфраструктура: Pinecone, Redis, Kubernetes.
* GDPR-compliance: шифрование at-rest, consent management.


* **Качество кода и техдолг:** Код поставляется в виде Docker-контейнера с настроенным `uv`. Кэш эмбеддингов и векторная база ChromaDB монтируются локально. В качестве техдолга оставляется асинхронная обработка очереди извлечения фактов (сейчас выполняется синхронно в основном потоке инференса).

### 1.4 Предпосылки решения

* **Данные:** Отсутствует размеченный датасет диалогов пользователей Mindly — работаем с нуля. Для бенчмарка используем собственный mini-набор (25 QA-пар) в стиле LongMemEval.
* **Модели:** LLM для чата и извлечения фактов — `openai/gpt-4o-mini` через OpenRouter. Embeddings — `sentence-transformers/all-MiniLM-L6-v2` (локально, 384d).

## 2. Методология

### 2.1 Постановка задачи

С технической точки зрения задача формулируется как построение Conversational Agent с внешним персистентным хранилищем фактов (Semantic Memory RAG).

* **Входные данные:** `user_id: str`, `persona: str`, `message: str`.
* **Выходные данные:** `Iterator[str]` (стриминг токенов ответа).
* **Операция forget:** `user_id: str, query: str | "all"` (физическое удаление документов из индекса).

### 2.2 Блок-схема решения

#### Архитектура Бейзлайна (Наивный RAG / Контекст истории)

Для бейзлайна используется стандартное окно контекста, куда передаются последние $N$ сообщений из истории, хранящейся в памяти сессии.

```
┌────────────────────────────────────────────────────────┐
│                   Baseline.chat()                      │
│                                                        │
│  user_id, message                                      │
│         │                                              │
│         ▼                                              │
│  ┌──────────────────────────────┐                      │
│  │ Загрузка последних N        │                      │
│  │ сообщений из памяти сессии  │                      │
│  └────────┬─────────────────────┘                      │
│           │                                            │
│           ▼                                            │
│  ┌──────────────────────────────┐                      │
│  │ Отправка в OpenRouter        │                      │
│  │ (Без извлечения фактов)      │                      │
│  └──────────────────────────────┘                      │
└────────────────────────────────────────────────────────┘

```

#### Архитектура Основного MVP (Mem0 Layer)

```
┌──────────────────────────────────────────────────────────────────┐
│                         MindlyAgent.chat()                       │
│                                                                  │
│  user_id, persona, message                                       │
│         │                                                        │
│         ▼                                                        │
│  ┌─────────────────┐     ┌──────────────────────────────────┐   │
│  │  Mem0.search()  │────►│  ChromaDB (векторный индекс)     │   │
│  │  user_id filter │◄────│  all-MiniLM-L6-v2 embeddings     │   │
│  └────────┬────────┘     └──────────────────────────────────┘   │
│           │ top-K факты                                          │
│           ▼                                                      │
│  ┌──────────────────────────────────────────────────────┐       │
│  │  Сборка messages:                                    │       │
│  │  [system: persona_prompt + known_facts]              │       │
│  │  [user: message]                                     │       │
│  └────────────────────────┬─────────────────────────────┘       │
│                           │                                      │
│                           ▼                                      │
│  ┌──────────────────────────────────────────────────────┐       │
│  │  OpenRouter API (openai/gpt-4o-mini)                 │       │
│  │  stream=True → Iterator[str]                         │       │
│  └────────────────────────┬─────────────────────────────┘       │
│                           │ токены                               │
│                           ▼                                      │
│                    Streamlit UI                                  │
│                                                                  │
│  После завершения стрима:                                        │
│  ┌──────────────────────────────────────────────────────┐       │
│  │  Mem0.add([user_msg, assistant_msg], user_id)        │       │
│  │  → LLM извлекает факты → ChromaDB                    │       │
│  └──────────────────────────────────────────────────────┘       │
└──────────────────────────────────────────────────────────────────┘

```

**Альтернативы:** Single context window отклонён (дорого, теряет факты при обрезке). Наивный RAG (хранение сырых чанков сообщений) отклонён, так как он не обеспечивает компрессию данных и тянет избыточный шум в промпт. MemGPT выбран как бэклог для Phase 2 из-за избыточной сложности для MVP.

### 2.3 Этапы решения задачи

#### Этап 1 — Подготовка данных и EDA

Данные генерируются в процессе работы. Источники существующих данных отсутствуют. Для валидации разметки создается синтетический датасет.

| Название данных | Есть ли данные в компании | Название источника/витрин | Требуемый ресурс для получения данных | Проверено ли качество данных |
| --- | --- | --- | --- | --- |
| Скрипты диалогов Mindly | Нет | Генерируются в сессиях | DS | Нет |
| Валидационный сет памяти | Да (Синтетика) | `data/eval_set.json` | DS / Эксперт | Да (Валидировано вручную) |

**Результат этапа:** JSON-витрина из 25 QA-пар для оценки полноты извлечения воспоминаний.

#### Этап 2 — Подготовка прогнозных моделей (Эксперименты)

* **Формирование выборки:** Тестовая выборка фиксируется в `data/eval_set.json`. Она содержит 25 сценариев. Каждый сценарий состоит из 3-5 реплик, содержащих скрытые факты (цели, медицинские противопоказания, имя, предпочтения в спорте), и 1 проверочного вопроса, задаваемого после условного "перезапуска" сессии.
* **Метрика качества:** Soft Exact Match (soft EM). Ответ считается верным ($1$), если ключевой сущностный токен содержится в текстовом ответе. Целевой показатель для MVP: $\text{soft EM} \ge 50\%$.
* **Риски:** Извлеченные факты могут дублироваться или противоречить друг другу при изменении мнения пользователя (например, сначала хотел похудеть, потом передумал). Для митигации Mem0 использует внутренний механизм апдейта фактов на базе LLM-компрессии.

## 3. Подготовка пилота

### 3.1 Способ оценки пилота

Оценка проводится в формате автоматического офлайн-тестирования на базе Mini LongMemEval. Скрипт инициализирует пустую базу ChromaDB, последовательно отправляет в `MindlyAgent.chat()` тренировочные реплики для `user_id`, затем вызывает метод очистки контекста сессии, после чего отправляет проверочный вопрос. Ответ сравнивается со строгим ожидаемым значением (ground truth) с помощью регулярных выражений и LLM-ассистента для проверки синонимов.

### 3.2 Что считаем успешным пилотом

* **Бизнес-критерий:** Инвестор вводит 3–5 фактов о себе, закрывает вкладку, открывает снова — агент приветствует его по имени и задает вопрос, опираясь на контекст прошлой беседы.
* **Технические критерии:**
* $\text{Soft EM} > 50\%$ на тестовом сете.
* $\text{TTFT (Time to First Token)} < 3$ секунд.
* $0$ случаев пересечения контекстов (утечки данных) между `demo_user_1` и `demo_user_2`.



### 3.3 Подготовка пилота

Векторная база инициализируется фикстурами со следующими данными:

* `demo_user_1` (Анастасия, цель — подготовка к марафону, вегетарианка, исключила мясо, ест морепродукты).
* `demo_user_2` (Дмитрий, цель — набрать мышечную массу, тренировки 3 раза в неделю, травма колена).

Вычислительная сложность на инференсе стабильна: 1 вызов эмбеддинг-модели локально (~50ms) + 1 поисковый запрос к ChromaDB SQLite (~10ms) + 1 генеративный запрос к API.

## 4. Техническое решение

### 4.1 Архитектура решения

```
[Streamlit UI] ---> [MindlyAgent Class] ---> [Mem0 Engine] ---> [ChromaDB (Local)]
                                        ---> [OpenRouter API (GPT-4o-Mini)]

```

Интеграция компонентов выполняется в рамках единого python-пакета. Стриминг реализуется через конструкцию `client.chat.completions.create(stream=True)`.

### 4.2 Описание инфраструктуры и масштабируемости

* **Архитектура MVP:** Локальный запуск в Docker. Векторный индекс ChromaDB пишется на диск в директорию `/app/data/vector_db`.
* **Плюсы:** Нулевая стоимость инфраструктуры, отсутствие сетевых задержек на запросы к БД, простота сборки демо.
* **Минусы:** Ограничение вертикального масштабирования. При переходе на Production (Phase 2) ChromaDB заменяется на Managed Pinecone, а Streamlit заменяется на связку FastAPI + React.

### 4.3 Требования к работе системы

* **SLA по доступности:** 99% в рамках демо-окна.
* **Пропускная способность:** До 10 одновременных пользователей (ограничено лимитами OpenRouter API).
* **Задержки (Latency):**
* Поиск в памяти: p95 < 200 ms.
* TTFT: p95 < 2000 ms.



### 4.4 Безопасность системы

* В MVP аутентификация отсутствует, `user_id` передается строкой из UI.
* Защита от Prompt Injection: данные из памяти подставляются в системный промпт с четкими разделителями секторов:

```text
<known_user_facts>
{facts}
</known_user_facts>

```

### 4.5 Безопасность данных

* Изоляция данных обеспечивается на уровне метаданных ChromaDB:

```python
memory.search(query=message, user_id=user_id)

```

* Соответствие GDPR (Art. 17) реализовано через метод удаления:

```python
memory.delete_all(user_id=user_id)

```

Данные в MVP хранятся в plaintext внутри SQLite. Для демо-режима персональные данные реальных физических лиц не используются.

### 4.6 Издержки

Расчетная стоимость запросов на gpt-4o-mini составляет около $0.05 на одного пользователя за сессию из 100 сообщений. Полная стоимость проведения демо с учетом тестирования не превысит $5. При масштабировании до 10k MAU целевые затраты составят $650/месяц.

### 4.7 Integration points

Контракт взаимодействия с основным бэкендом:

```python
class MindlyAgent:
    def chat(self, user_id: str, persona: str, message: str, stream: bool = True):
        pass

    def forget(self, user_id: str, query: str):
        pass

```

### 4.8 Риски

* **R1 (Утечка данных):** Ошибки фильтрации. Митигация: интеграционный тест `test_isolation.py`, проверяющий доступ к базе под случайными ID.
* **R2 (Исчерпание лимитов API):** Блокировка токена OpenRouter во время демо. Митигация: привязка резервной карты и подготовка дублирующего аккаунта OpenAI API с прописанным в `.env` ключом.
