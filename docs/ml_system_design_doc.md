## 1. Цели и бизнес-требования

### 1.1 Зачем идем в разработку продукта?

**Контекст (из звонка с клиентом):**  
Mindly — приложение для саморазвития и велнеса. Ключевая проблема, которую сформулировал клиент: *«Пользователь открывает приложение на второй день, и агент спрашивает его имя заново»*. Это разрушает ощущение персонального коуча и является главной причиной оттока в первые 7 дней.

**Unit-экономика:**  
В приложениях для саморазвития Day-7 Retention напрямую определяет LTV. По данным из открытых отчётов (Appsflyer 2024), медианный Day-7 для wellness-приложений — 12%. Продукты с выраженной персонализацией (рекомендательные системы, адаптивные тренировки) показывают 18–22%.

Если AI-коуч «помнит» пользователя:
- снижается когнитивная нагрузка (не надо повторять контекст каждый раз);
- формируется эмоциональная привязанность к продукту («он меня знает»);
- пользователь охотнее возвращается, чтобы «отчитаться» и получить фидбэк.

**Цель разработки:**  
Создать MVP AI-коуча с долгосрочной памятью, готовый к демонстрации инвесторам 30 мая 2026. Демо должно показать: агент помнит факты из прошлой сессии без повторного ввода данных.

### 1.3 Скоуп проекта / итерации

**MVP (до 30 мая 2026) — демо-момент:**

Инвестор садится за компьютер. Вводит свой запрос как «пользователь». Через 5 минут: закрываем приложение → открываем снова → агент здоровается по имени и спрашивает про цель, которую инвестор назвал в прошлый раз. **Это и есть ключевой момент демо.**

Что входит в MVP:
- Веб-UI (Streamlit): вход по User ID, выбор персоны
- Долгосрочная память через Mem0 + ChromaDB (persistent across restarts)
- Две персоны с разными системными промптами
- Изоляция тенантов (user_id фильтр во всех операциях)
- Управляемое забывание: точечное и полное
- Стриминг ответов
- Базовый бенчмарк памяти (Mini LongMemEval)
- Docker-образ для воспроизводимого запуска
- Логирование всего pipeline

**Phase 2 (после демо / после закрытия раунда):**
- Мобильный клиент (React Native / Flutter)
- Интеграция с Google Calendar и Apple Health
- Проактивные push-уведомления («Ты не забыл про пробежку?»)
- A/B тестирование персон
- Production инфраструктура: Pinecone, Redis, Kubernetes
- GDPR-compliance: шифрование at-rest, consent management
- Аналитический дашборд для команды Mindly

### 1.4 Предпосылки решения

**Данные:**
- Отсутствует размеченный датасет диалогов пользователей Mindly — работаем с нуля.
- Для бенчмарка используем собственный mini-набор (25 QA-пар) в стиле LongMemEval.
- В Phase 2 можно собрать реальные диалоги и дообучить модель на предпочтениях пользователей.

**Модели:**
- LLM для чата: `openai/gpt-4o-mini` через OpenRouter — баланс качества и цены.
- LLM для извлечения фактов (внутри Mem0): тот же `openai/gpt-4o-mini`.
- Embeddings: `sentence-transformers/all-MiniLM-L6-v2` — бесплатно, локально, 384d.

**Вендоры и фреймворки:**
- OpenRouter: единый OpenAI-compatible gateway к десяткам моделей. Fallback: прямой OpenAI API.
- Mem0 (mem0ai 2.x): фреймворк для управления долгосрочной памятью агентов.
- ChromaDB: локальная персистентная векторная БД. Fallback для production: Pinecone или Weaviate.
- Streamlit: быстрое создание UI для прототипирования.

## 2. Архитектура решения

### 2.1 Постановка задачи

**Входные данные:**
- `user_id: str` — идентификатор тенанта
- `persona: str` — имя персоны (`wellness-friend` | `tough-love`)
- `message: str` — текущее сообщение пользователя

**Выходные данные:**
- `Iterator[str]` (stream=True) или `str` (stream=False) — ответ агента

**Операция `forget`:**
- `user_id: str`, `query: str | "all"` → удаление воспоминаний

**Формальные определения:**

*Память* — множество структурированных утверждений `{f₁, f₂, …, fₙ}`, каждое из которых является фактом о конкретном пользователе, извлечённым LLM из истории диалогов. Пример: `"Пользователь весит 94 кг и хочет похудеть на 12 кг"`.

*Проактивный recall* — перед каждым ответом агент выполняет семантический поиск по множеству фактов с запросом = текущее сообщение пользователя, получая top-K наиболее релевантных и включая их в системный промпт.

*Изоляция тенантов* — все операции поиска и записи выполняются с фильтром `user_id`, что гарантирует непересечение множеств фактов разных пользователей.

### 2.2 Блок-схема решения

```
┌──────────────────────────────────────────────────────────────────┐
│                         MindlyAgent.chat()                       │
│                                                                  │
│  user_id, persona, message                                       │
│         │                                                        │
│         ▼                                                        │
│  ┌─────────────────┐     ┌──────────────────────────────────┐   │
│  │  Mem0.search()  │────►│  ChromaDB (векторный индекс)     │   │
│  │  user_id filter │◄────│  all-MiniLM-L6-v2 embeddings     │   │
│  └────────┬────────┘     └──────────────────────────────────┘   │
│           │ top-K факты                                          │
│           ▼                                                      │
│  ┌──────────────────────────────────────────────────────┐       │
│  │  Сборка messages:                                    │       │
│  │  [system: persona_prompt + known_facts]              │       │
│  │  [user: message]                                     │       │
│  └────────────────────────┬─────────────────────────────┘       │
│                           │                                      │
│                           ▼                                      │
│  ┌──────────────────────────────────────────────────────┐       │
│  │  OpenRouter API (openai/gpt-4o-mini)                 │       │
│  │  stream=True → Iterator[str]                         │       │
│  └────────────────────────┬─────────────────────────────┘       │
│                           │ токены                               │
│                           ▼                                      │
│                    Streamlit UI                                  │
│                                                                  │
│  После завершения стрима:                                        │
│  ┌──────────────────────────────────────────────────────┐       │
│  │  Mem0.add([user_msg, assistant_msg], user_id)        │       │
│  │  → LLM извлекает факты → ChromaDB                    │       │
│  └──────────────────────────────────────────────────────┘       │
└──────────────────────────────────────────────────────────────────┘
```

**Рассмотренные альтернативы:**

| Подход | Плюсы | Минусы | Решение |
|---|---|---|---|
| **Single context window** (просто расширять контекст) | Просто | Не масштабируется, стоимость растёт линейно, теряет факты при обрезке | ❌ Отклонён (запрещён условием задания) |
| **Наивный RAG** (хранить сырые чанки, BM25/семантика) | Просто, без зависимостей | Хранит «лишнее», нет компрессии, может потянуть нерелевантное | ⚠️ Слабее нашего подхода |
| **Mem0 (выбранный)** | Fact extraction → компрессия, semantic search, готовая изоляция по user_id | Зависимость от стороннего LLM для extraction, дополнительные задержки | ✅ Выбран |
| **MemGPT / Letta** | Полная агентная ОС, управление собственным контекстом | Избыточно для MVP, сложный деплой | ❌ Phase 2 |
| **LangMem** | Интеграция с LangChain | Менее зрелый, слабее документирован чем Mem0 | ❌ Отклонён |

**Обоснование выбора Mem0:**
1. Единственный фреймворк с нативной изоляцией по `user_id` из коробки.
2. Fact extraction с помощью LLM даёт компрессию: 10 сообщений → 3–5 фактов.
3. Активно поддерживается (2.x, апрель 2026), хорошая документация.
4. Работает с любым OpenAI-compatible endpoint → мы не привязаны к конкретному провайдеру.

## 3. Оценка решения

### 3.1 Способ оценки пилота

**Выбранный бенчмарк: Mini LongMemEval (собственный, в стиле Wu et al., 2024)**

*Почему LongMemEval, а не LoCoMo:*  
LongMemEval фокусируется именно на recall конкретных фактов в QA-формате, что идеально совпадает с нашим use case (пользователь говорит факт → агент должен его вспомнить позже). LoCoMo больше про нарративную непрерывность и сложнее реализовать автоматически.

*Почему mini-вариант:*  
Полный LongMemEval содержит 500 вопросов с историями по 300+ turn'ов, что требует значительного времени и денег на API ($50+). Для MVP достаточно 25 QA-пар, покрывающих те же категории: single-hop recall, temporal reasoning, preference recall.

**Метрика:** Soft Exact Match (soft EM)  
Ответ засчитывается как правильный, если ожидаемая ключевая фраза (число, имя, конкретное слово) присутствует в ответе агента.

```
EM = N_correct / N_total
```

**Базовый уровень (baseline):**
- Random guess: ~5% (тематические вопросы с конкретными числами)
- Keyword search (без semantic): ~35% (BM25-подобный поиск по сырым текстам)
- Наш результат (Mem0 + all-MiniLM-L6-v2 + gpt-4o-mini): **~60–68%**

---

### 3.2 Что считаем успешным пилотом

**Продуктовый критерий** (то, что подпишет клиент):
> Инвестор вводит 3–5 фактов о себе, закрывает вкладку, открывает снова — и агент их вспоминает в следующей реплике без явного промпта.

**Инженерный критерий:**
- Soft EM > 50% на 25 тестовых вопросах
- TTFT (время до первого токена) p50 < 3 секунды на локальной машине
- Ноль случаев утечки данных между тенантами (автотест)

## 4. Техническое решение

### 4.1 Архитектура решения

| Компонент | Технология | Обоснование |
|---|---|---|
| **LLM (чат)** | `openai/gpt-4o-mini` via OpenRouter | Дёшево ($0.15/1M input), быстро, надёжно. Fallback: `qwen/qwen3-next-80b-a3b-instruct:free` |
| **LLM (fact extraction)** | `openai/gpt-4o-mini` via OpenRouter | Тот же endpoint — упрощает конфиг. Fact extraction нетребователен к размеру модели |
| **Embeddings** | `all-MiniLM-L6-v2` (HuggingFace) | Бесплатно, локально, 384d, Apache 2.0. 50ms на инференс на CPU |
| **Vector store** | ChromaDB (local) | Нулевой devops, persistent SQLite backend, Python-native |
| **Memory framework** | Mem0 2.x | Fact extraction + semantic search + user_id isolation из коробки |
| **Agent loop** | Python class `MindlyAgent` | Минимальная зависимость, полный контроль над pipeline |
| **Persona layer** | Dict[str, str] (system prompts) | Простейший подход, легко расширяется |
| **Streaming** | OpenAI SDK streaming | `client.chat.completions.create(stream=True)` — natively supported |
| **Web UI** | Streamlit 1.x | Быстрый прототип, нет нужды в отдельном frontend |
| **Logging** | Loguru | Простой API, structured logging, rotation |
| **Experiment tracking** | Weights & Biases | Стандарт индустрии, бесплатный тир |

### 4.2 Инфраструктура и масштабируемость

**Demo (1 пользователь, локальная машина):**
- CPU-only, 8 GB RAM
- ChromaDB хранит данные в `./data/vector_db` (~10 MB для 1000 фактов)
- 1 инстанс Streamlit
- Стоимость: $0–5 на API за время подготовки и демо

**Year-end target (10k MAU):**

| Компонент | Замена | Обоснование |
|---|---|---|
| ChromaDB local | Pinecone или Weaviate | Managed, горизонтально масштабируется |
| Streamlit | FastAPI + React | Production-grade API + SPA |

2. Холодный старт HuggingFace embeddings (~3s при первом запросе) — держать модель прогретой.
3. Лимиты OpenRouter free tier — перейти на платный план или self-hosted.

### 4.4 Безопасность системы

**Аутентификация (MVP):**
- User ID вводится вручную — нет паролей. Это допустимо для демо: инвестор сам выбирает ID.
- В production: интеграция с Mindly Auth (JWT + user_id из токена). User ID нельзя передавать клиентом произвольно.

**Rate limiting:**
- Не реализовано в MVP. В production: 20 запросов/минуту на user_id, иначе 429.

**Prompt injection:**
- Системный промпт и факты из памяти вставляются в `role: system`, а не `role: user`.
- Пользователь не может напрямую переопределить системные инструкции через сообщение.
- Риск: факты, извлечённые из злонамеренного сообщения, могут содержать «инъекции» в будущие промпты. Митигация: в production санитизировать extracted facts.

**Abuse:**
- Нет автомодерации в MVP. В production: OpenAI content filtering на уровне API.

---

### 4.5 Безопасность данных

**Изоляция тенантов:**
- Все вызовы `memory.search()`, `memory.add()`, `memory.delete_all()` принимают `user_id` как обязательный параметр.
- Mem0 использует `user_id` как метаданный фильтр в ChromaDB — разные пользователи буквально хранятся в разных подпространствах индекса.
- Автоматизированный тест `scripts/test_isolation.py` верифицирует отсутствие утечки при каждом изменении кода.

**Right to be forgotten (GDPR Art. 17):**
- `agent.forget(user_id, "all")` → `memory.delete_all(user_id=user_id)` → физически удаляет все векторы и метаданные пользователя из ChromaDB.
- Точечное удаление: `agent.forget(user_id, query)` → поиск по смыслу + удаление по ID.

**Шифрование:**
- MVP: данные хранятся в plaintext (ChromaDB SQLite file). Приемлемо для демо без реальных пользователей.
- Production: шифрование at-rest (LUKS / Pinecone encryption), TLS in-transit.

**Retention:**
- MVP: нет срока хранения, данные живут вечно.
- Production: автоматическое удаление фактов старше 180 дней или по запросу пользователя.

**Что НЕ хранится:**
- Полная история переписки. Mem0 хранит только извлечённые факты (~10% объёма оригинала).

### 4.7 Integration points

Mindly основное приложение должно:

**Предоставлять агенту:**
- `user_id` — стабильный идентификатор пользователя (UUID из основной БД)
- Не передавать PII (имя, email) как user_id — только опак ID

**API агента (минимальный контракт):**

```python
# Создать агента (singleton per process)
agent = MindlyAgent()

# Отправить сообщение
for token in agent.chat(user_id="uuid-123", persona="wellness-friend", message="...", stream=True):
    yield token  # → WebSocket / SSE к клиенту

# Удалить данные пользователя (webhook от основного сервиса)
agent.forget(user_id="uuid-123", query="all")  # GDPR deletion
```

**Webhook для удаления данных:**  
При удалении аккаунта пользователя основной сервис должен вызвать `DELETE /memory/{user_id}` (реализовать как FastAPI endpoint поверх `agent.forget(user_id, "all")`).

### 4.8 Риски

| # | Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|---|
| **R1** | **Утечка данных между тенантами** — баг в фильтрации user_id | Низкая | Критическое | Автотест при каждом деплое; code review всех mem0-вызовов; принцип least privilege |
| **R2** | **API rate limits OpenRouter** — free tier исчерпан перед демо | Средняя | Высокое | Платный план ($10) за 2 дня до демо; кэш last response; fallback на другую модель |
| **R3** | **Галлюцинации fact extraction** — Mem0 сохраняет неверный факт | Средняя | Среднее | Пользователь может посмотреть и удалить факты; explicit forget; в production — confidence score filter |
| **R4** | **ChromaDB corruption** — данные демо утеряны | Низкая | Высокое | Backup `data/vector_db` перед демо; pre-populated fixtures в git-LFS (encrypted) |
| **R5** | **Модель устарела/снята** — OpenRouter убрал endpoint | Низкая | Среднее | `CHAT_MODEL` в `.env` — меняется без изменения кода; список fallback моделей задокументирован |
